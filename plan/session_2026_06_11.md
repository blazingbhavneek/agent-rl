### 2. Inventoried available reward signals for weighted SFT

Each episode writes `metadata.json`. Current signals:

#### Stubs (`_trace_dataset/episodes/stubs/<safe>/<eid>/metadata.json`)
| Field | Type | Meaning |
|---|---|---|
| `validated` | bool | stub compiled + has `__wrap_F`, no `__real_F` |
| `body_chars` | int | stub size in chars |

#### Unit tests (`_trace_dataset/episodes/unit_tests/<safe>/<eid>/metadata.json`)
| Field | Type | Meaning |
|---|---|---|
| `passed` | bool | test suite passed |
| `coverage_pct` | float | gcov line coverage % |
| `semantic_score` | float | LLM judge score |
| `make_ok` | bool | compilation succeeded |

#### Selection key already defined
`_unit_sort_key` ranks by `(passed, coverage_pct, semantic_score)` — same composite is natural SFT weight.

#### SFT training tuple shape
```
agent_history/_gen_stub_<safe>.prompt.txt   → prompt
agent_history/_gen_stub_<safe>.result.json  → completion
metadata.json[validated / coverage_pct / semantic_score] → weight
```

All three components already on disk per episode. No new collection needed — just a reader that loads episodes, filters by signal threshold, emits weighted (prompt, completion) pairs.
